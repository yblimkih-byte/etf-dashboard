# ETF Dashboard 설치 가이드 (Google Apps Script)

구조: 스프레드시트 `ETF_Dashboard` 에 내장된 Apps Script 1개가 (1) 매일 KRX 데이터 적재, (2) 집계, (3) 웹앱(URL) 제공을 모두 수행함. 별도 서버·Zapier 불필요.

```
[KRX Open API] ──┐                         ┌─ raw_일별 (2026-01-02~, 영업일)      ┌─ agg_* 집계 시트
[data.krx.co.kr]─┼─ loadDaily (08:30/19:00) ┼─ raw_월말 (2021-01~, 월말 스냅샷)  ─┼─ 웹앱 doGet/api ─→ 대시보드 URL
[Yahoo 지수]     ─┘                         └─ ETF마스터 / 범례_유형·범례_운용사(사용자) / 지수 / agg_월말요약·agg_일별요약
```

## 1. 코드 설치 (약 10분)

1. `ETF_Dashboard` 시트 열기 → 메뉴 **확장 프로그램 > Apps Script**
2. 기본 생성된 `Code.gs` 삭제 후, `gas/` 폴더의 파일을 **같은 이름으로** 모두 추가
   - 스크립트 파일(+ 버튼 > 스크립트): `Config`, `Util`, `Krx`, `Load`, `Backfill`, `Aggregate`, `Api`, `Setup`
   - HTML 파일(+ 버튼 > HTML): `Index`, `Style`, `App`, `Tabs`
   - 좌측 **프로젝트 설정(⚙)** > "appsscript.json 매니페스트 파일 표시" 체크 → `appsscript.json` 내용을 붙여넣기(시간대 Asia/Seoul, 웹앱 익명 접근)
3. 저장 후 스프레드시트를 **새로고침** → 상단에 `ETF Dashboard` 메뉴 생김 (첫 실행 시 권한 승인 필요)

## 2. 초기 데이터 적재 (메뉴 순서대로)

| 순서 | 메뉴 | 내용 | 소요 |
|---|---|---|---|
| 1 | API 키 설정 | KRX Open API AUTH_KEY 입력 (스크립트 속성에 저장, 코드에 노출되지 않음) | 즉시 |
| 2 | 시트 생성(초기화) | raw_일별 / raw_월말 / ETF마스터 / 지수 / _index / _log 생성, 범례_유형 L열에 `확인필요` 헤더 추가 | 즉시 |
| — | **API 연결 테스트** | 최근 영업일 응답 건수·필드명 표시. **여기서 실패하면 아래 "문제 해결" 참조** | 즉시 |
| 3 | 월말 백필 시작 | 2021-01 ~ 2025-12 월말 스냅샷 (60개월). 6분 예산 초과 시 1분 후 자동 재시작 | 10~20분 |
| 4 | 일별 백필 시작 | 2026-01-02 ~ 오늘 (약 170영업일). 마찬가지로 자동 이어서 실행 | 20~40분 |
| 5 | 지수 백필 | KOSPI·S&P500·NASDAQ100 일별 종가 2021-01~ (Yahoo Finance, 키 불필요; KOSPI는 실패 시 KRX API 보완) | 1분 |
| 6 | 매일 자동 적재 트리거 설치 | 매일 08:30(전영업일분) / 19:00(당일분 게시 시) `loadDaily` 실행 | 즉시 |
| 7 | 상장일 보정 (최초 등장일) | ETF마스터 상장일 공란을 범례_유형 설정일 → raw 최초 등장일로 채움 (신규상장 탭에 사용) | 1~2분 |
| 8 | 일별 요약 재작성 | agg_일별요약(일자별 운용사×유형 요약) 최초 생성. 6분 초과 시 자동 이어서 실행. 이후 일별 적재 시 자동 추가 | 5~8분 |

진행 상황은 `_log` 시트에서 확인. 백필 중 중단하려면 "백필 중단(트리거 제거)".

## 3. 웹앱 배포 (URL 발급)

1. Apps Script 편집기 우상단 **배포 > 새 배포** → 유형 "웹 앱"
2. 실행 계정: **나**, 액세스 권한: **모든 사용자(익명 포함)** → 배포
3. 발급된 `https://script.google.com/macros/s/…/exec` 가 대시보드 URL (로그인 불필요)
4. 코드 수정 후에는 **배포 > 배포 관리 > 편집 > 새 버전** 으로 갱신해야 URL에 반영됨 (테스트는 "테스트 배포" URL 사용)

## 4. 매일 운영 방식

- `loadDaily`: 마지막 적재일 다음 영업일부터 오늘까지 순차 적재. 최근 3일 이내 빈 응답은 "미게시"로 보고 다음 실행에 재시도, 그 이전 빈 날짜는 휴장으로 건너뜀
- 신규 ETF 발견 시: data.krx.co.kr 전종목 기본정보에서 운용사·기초자산 조회 → `ETF마스터` 추가, `범례_유형`에 규칙 기반 유형 + L열 `확인필요` 표시, 새 운용사는 `범례_운용사`에 상위구분 `기타`로 추가
  - **월말에 `범례_유형`을 L열 `확인필요` 로 필터해 유형 검토·수정** 후 메뉴 "집계 재계산" 실행 (L열 값은 지워도 됨)
- 매 적재 후 `agg_*` 집계 시트 전체 재계산 + 당일 요약을 `agg_일별요약`에 추가 + API 응답 캐시 예열(warmCache) → 대시보드는 요약·집계 시트만 읽고, 같은 조회는 CacheService 캐시(6시간, 데이터 변경 시 자동 무효화)로 즉시 응답
- 기준일자 목록: 지난 달까지는 `연-월`(월말 스냅샷), 이번 달은 영업일 날짜 전체
- 시트 용량: raw_일별 연 약 25만 행 × 8열 = 200만 셀/년. 한도(1,000만 셀) 기준 약 4년분. 이후 연도별 시트 분리 필요(추후 작업)

## 5. 시트 설명

| 시트 | 작성 | 내용 |
|---|---|---|
| 범례_유형 | 사용자 | 종목코드/ETF명/설정일/유형1~4/유형최종1/유형최종2/국내해외/신규상장용 (+L열 확인필요, 자동) |
| 범례_운용사 | 사용자 | 운용사명/약식_한글/약식_정식/약식_상위/운용사명_상위. 대시보드 표시명 = 약식_정식, 상위 5개사 그룹 = 약식_상위(삼성/미래/KB/한투/신한, 그 외 기타) |
| raw_일별 | 자동 | 기준일자/종목코드/종목명/자산운용사/순자산총액/거래대금/해당연도거래대금계/해당월거래대금계 |
| raw_월말 | 자동 | 동일 컬럼. 각 월의 마지막 영업일(당월은 최근 영업일). 2025년 이전은 누적 거래대금 공란 |
| ETF마스터 | 자동 | 종목코드/종목명/운용사명(=범례 약식_정식)/브랜드/상장일/기초시장/기초자산/출처. 열은 헤더명으로 인식. 운용사 매칭 우선순위: 브랜드 열 → 운용사명 → 종목명 접두어 |
| 지수 | 자동 | 일자/KOSPI/S&P500/NASDAQ100 |
| 투자자별순매수 | 자동(선택) | 기준일자/운용사/투자자/순매수대금 — `CFG.KRX_WEB.INVESTOR_ENABLED=true` 시 적재 |
| _index / _log | 자동 | 일별 블록 위치 인덱스 / 실행 로그 |
| agg_* | 자동 | 월별 시장·운용사·유형·운용사×유형·상위ETF 집계, agg_월말요약(월말 스냅샷별 운용사×유형×국내해외), agg_일별요약(일자별 동일 요약) |

## 6. 설정 변경 (Config.gs)

- `TOP5`, `COLOR`: 상위 운용사와 고유색. 값은 `범례_운용사`의 약식_상위와 일치해야 함
- `TYPE_ORDER`: 유형 표시 순서 (`범례_유형` 유형최종2 값)
- `MONTHLY_FROM`, `DAILY_FROM`: 데이터 시작점
- `BRAND_MAP`: 종목명 접두어 → 운용사 기본값. **`범례_운용사` 브랜드 열이 우선**하며, 첫 단어가 브랜드와 같거나 브랜드로 시작하면(TIME → TIMEFOLIO) 매칭
- `범례_운용사` 열은 헤더명(운용사명/브랜드/약식_한글/약식_정식/약식_상위/운용사명_상위)으로 인식하므로 열 순서를 바꿔도 됨
- `KRX_WEB.*`: data.krx.co.kr 화면 식별자(bld)·필드명

## 7. 문제 해결

| 증상 | 원인·조치 |
|---|---|
| API 연결 테스트 401/403 | 키 오류 또는 **"ETF 일별매매정보" 서비스 이용신청 미승인**. KRX Open API 마이페이지에서 승인 확인 |
| 연결 테스트 응답 없음/타임아웃 | KRX가 Google 서버(해외 IP) 접근을 차단하는 경우. 이 경우 적재 주체를 국내(GitHub Actions 불가, 국내 PC/NAS)로 옮겨야 하며 웹앱·집계 코드는 그대로 사용 가능 — 별도 상담 필요 |
| `_log`에 "ETF 기본정보 웹조회 실패" | data.krx.co.kr 화면 식별자 변경. 브라우저에서 해당 화면 열기 → F12 > Network > `getJsonData.cmd` 요청의 `bld` 값과 응답 필드명을 `CFG.KRX_WEB.BASIC_BLD / BASIC_F` 에 반영. 실패 시에도 브랜드 접두어로 운용사 추정하므로 적재는 계속됨 |
| 신규 ETF 운용사 `미확인` | `범례_운용사` **브랜드** 열에 해당 브랜드(예: KODEX, TIGER — 브랜드별 행을 나눠도 됨)를 추가한 뒤 메뉴 "운용사 보정 (범례_운용사 반영)" 실행(ETF마스터·raw 운용사 열 갱신 후 집계 재계산). 신규 종목은 이후 자동 적용. 브랜드가 없는 종목은 `ETF마스터`에 운용사명 직접 입력 후 "집계 재계산" |
| 지수 공란 | Yahoo Finance 응답 실패. "5. 지수 백필" 재실행 또는 `지수` 시트에 직접 입력(일자 오름차순 유지) |
| 대시보드 "해당 일자 데이터 없음" | 선택 일자의 스냅샷 부재. 월말 백필/일별 백필 완료 여부 확인 |
| 실행 시간 초과 | 자동으로 1분 후 이어서 실행됨. 트리거 목록(시계 아이콘)에서 확인 |
| 갑자기 401 (그동안 정상) | KRX 인증키 유효기간 만료 → 마이페이지에서 키 갱신 후 스크립트 속성 `KRX_AUTH_KEY` 교체 |
| 배포 직후 기준일자 목록이 비어 있음 | 이전 버전 서버가 만든 API 응답 캐시. 메뉴 "집계 재계산"(캐시 버전 갱신) 후 새로고침 |
| 신규상장 탭 비어 있음 | ETF마스터 상장일 공란. 메뉴 "상장일 보정 (최초 등장일)" 실행 |
| 월말 NAV 0 / 그래프 급락 | KRX는 휴장일(12/31·공휴일)에도 전 종목 0 값을 반환. 현재 코드는 자동 제외하며, 과거 적재분은 메뉴 "NAV 0 일자 보정" 1회 실행 후 "3. 월말 백필 시작"으로 해당 월 재적재 |
| 이번 달 기준일자 선택 시 시장개관 NAV 전부 0 | KRX API는 당일 19:00 시점에 거래대금만 먼저 게시하고 순자산총액(NAV)은 다음 영업일에 게시하는 경우가 있음. v9부터 전 종목 NAV 0 응답은 "미게시"로 보고 적재하지 않으며 다음 실행(08:30)에 재시도. 이미 0으로 적재된 일자가 있으면 메뉴 "NAV 0 일자 보정" 실행 → 해당 일자 raw_일별·agg_일별요약·당월 스냅샷을 제거하고 마지막 정상 일자로 재집계(다음 loadDaily 에서 자동 재적재) |

## 8. 알려진 제약

- 거래대금 from-to 조회는 일별 데이터 보유 구간(2026-01-02 이후)만 가능. 2021~2025년은 월말 NAV 스냅샷만 보유
- 상위 5개사 색상 중 미래(주황)·KB(금색)는 색약 시 구분이 약해 모든 차트에 운용사명 표기·표를 병기함. 한투 갈색은 채도가 낮아 회색(기타)과 근접 → 필요 시 `CFG.COLOR` 조정
- Apps Script 일일 한도: UrlFetch 20,000회/일, 실행 6분/회, 트리거 총 90분/일. 일상 운영은 하루 수십 회 수준으로 여유
- "ETF별 순매수 주체" 웹 자료는 종목 수만큼 웹 호출이 필요해 기본 비활성. 활성화 시 별도 트리거로 분리 권장
